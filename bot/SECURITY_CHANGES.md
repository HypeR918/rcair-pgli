# Исправления безопасности и надёжности

Изменения относятся к основному боту и GLPI importer. Режим подтверждения email и отдельный прототип не изменены.

## Что исправлено

- Каждый доступ к заявке проверяет текущую блокировку пользователя, активность учётной записи и участие заявителем в GLPI. Проверка применяется и к уведомлениям. Локальная связь с заявкой больше не служит доказательством доступа.
- Старые кнопки не принимают и не отклоняют решение, если заявка больше не находится в статусе «Решена»; нельзя добавить комментарий к уже закрытой заявке.
- Обновления одного MAX ID выполняются последовательно. Это предотвращает создание двух заявок при одновременном подтверждении одного черновика в одном процессе бота. Несколько экземпляров бота с общей БД этим механизмом не синхронизируются.
- Неожиданная ошибка обязательной миграции прерывает запуск. Сохранение/удаление сессий ожидается; кэш обновляется после успешной записи БД и возвращает копию состояния. Ошибки обработчиков не завершают весь процесс.
- Блокировка/разблокировка не используют удалённую колонку `bot_users.updated_at`; изменения в БД бота выполняются транзакционно. Запись в отдельную БД GLPI по-прежнему best-effort.
- Ограничение частоты отправки кодов хранится в `bot_verification_limits`, по MAX ID и хэшу email. `/start` и перезапуск процесса его не сбрасывают. Неуспешная попытка отправки письма также расходует cooldown.
- Очередь СДС обходит все заявки на начало прохода страницами по 20. Одобрение/отказ фиксируется после выполнения обработки и уведомления. При сбое возможна повторная доставка сообщения; недоставленное уведомление не теряется из очереди. Удалённая из GLPI заявка получает `MISSING`, а не `APPROVED`.
- GLPI-запросы имеют таймауты и ограничение полной длительности. SMTP использует `SMTP_USER`/`SMTP_PASS`, если они заданы; relay без авторизации поддерживается.
- Importer отказывается запускаться без `GLPI_IMPORT_SECRET`, проверяет секрет в постоянное время, выполняет один импорт одновременно (остальным — 429), не возвращает stdout/stderr команды клиенту.
- Зависимости обновлены; `npm start` запускает `index.js`; добавлены регрессионные тесты на встроенном `node:test`.

## Вложения

Разрешён HTTPS на порту 443 без userinfo. По умолчанию разрешены поддомены `max.ru`. Другие реальные домены хранилища задаются через `MAX_ATTACHMENT_ALLOWED_HOSTS` — список через запятую. Точное имя разрешает один хост; запись с начальной точкой разрешает его поддомены. Например: `.max.ru,files.example.org`. Не добавляйте недоверенные домены.

Проверяется каждое перенаправление (максимум три), а DNS-адрес проверяется при создании соединения. Локальные, частные и служебные адреса запрещены. Токен отправляется только `platform-api2.max.ru`, `platform-api.max.ru`, `api.max.ru`. На CDN токен не передаётся. Скачивание устанавливает прямое HTTPS-соединение: переменные HTTP_PROXY/HTTPS_PROXY для этой операции не используются, чтобы сохранить проверку адреса сокета. В сети с обязательным прокси потребуется отдельное поддерживаемое решение, а не отключение проверок.

Лимиты по умолчанию:

| Переменная | Значение |
| --- | --- |
| `MAX_ATTACHMENT_BYTES` | 20 МиБ на файл |
| `MAX_DRAFT_FILES` | 10 файлов |
| `MAX_DRAFT_BYTES` | 50 МиБ на черновик/сообщение |
| `UPLOAD_TTL_MS` | 24 часа |
| `GLPI_API_TIMEOUT_MS` | 30 секунд; загрузка документа — минимум 120 секунд |

Частичные файлы удаляются при ошибке. При запуске и раз в час удаляются просроченные файлы с новым префиксом `max-upload-` в `TEMP_UPLOAD_DIR`. Посторонние файлы и старые файлы предыдущей версии автоматически не удаляются.

## Проверка и обновление

В `bot/`: `npm ci`, затем `npm test`. Unit-тесты не требуют рабочих сервисов и секретов. Один интеграционный тест пропускается, если `RCAIR_TEST_DB_PORT` не задан.

Для полного набора поднимите отдельную временную MariaDB 11.4 на loopback с пустым паролем root (только тестовый контейнер), затем выполните `RCAIR_TEST_DB_PORT=<порт> npm test`. Тест создаёт уникальную БД `rcair_test_*`, проверяет настоящие миграции, откат транзакций, права и лимиты, затем удаляет её. Рабочие `BOT_DB_*`/`GLPI_DB_*` в этом тесте не используются.

Перед развёртыванием сохраните резервную копию БД бота. При старте появится дополнительная таблица `bot_verification_limits`; используйте ту же версию файлов и package-lock при установке зависимостей. Обновите также отдельно развёрнутый importer, сохранив его существующий секрет и ограничение сетевого доступа. Изменения не отправляются на сервер автоматически.

После развёртывания локально проверьте вход в выбранном вами режиме, создание заявки с фото/файлом, комментарий, решение и регистрацию СДС. Без рабочих сервисов эти сквозные сценарии здесь не проверяются.
